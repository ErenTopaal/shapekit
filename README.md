# shapekit

A test kit for software that reads the Stellar ledger.

Indexers and SDKs keep breaking on rare but valid transaction and ledger shapes: signed-payload
signers, muxed accounts, deep Soroban authorization trees, trustlines created by the Stellar
Asset Contract, and so on. Each team finds the same bugs on its own. shapekit is meant to be the
shared set of those shapes plus the tools to run them against an indexer or an SDK.

It is being built in response to the SDF RFP "XDR/CAP-Coverage Audit Tool and Indexer-Hardening
Guide".

## Status

Only the repository foundation exists so far. Nothing below the "Planned" heading is built yet.
The dated log of what has landed is in [STATUS.md](STATUS.md).

What exists today:

- `pins.toml`, the list of every upstream release, commit and container image the project
  builds on, and `shapekit pins verify`, which checks each of them still exists upstream.
- The Rust workspace, the Go modules in `go.work` and the JavaScript testee package, each with
  the minimum needed to build and test in CI.
- CI in `.github/workflows/`: formatting, linting and tests for Rust, Go and JavaScript, a check
  that no tracked file contains an em dash, and a weekly upstream drift report.

## Planned

How the planned parts map to the RFP deliverables:

| RFP deliverable | Planned part of shapekit |
|---|---|
| Corpus and generator with a per-CAP coverage manifest | `corpus/` (XDR files plus a language-neutral manifest with expected decoded values), generated by a local standalone stellar-core for both the testnet and mainnet passphrases, checked against stellar-core's `--check-lcm` goldens |
| Replay harness with an adapter interface and one reference adapter | `shapekit-harness`, serving ledgers in the SEP-54 (Galexie) layout and through a replay RPC, with a wallet-backend adapter in `adapters/` |
| Linter plus checklist | `lint/`, Go analyzers for the three ingestion mistakes in the RFP |
| Indexer-hardening guide | `docs/guide/`, written for developers.stellar.org |
| Conformance runner for JS, Go and Rust SDKs | `shapekit-conformance` and the testees in `testees/` |
| Findings reports | `findings/`, one entry per finding with its upstream issue |
| Test suite, CI, release and maintenance plan | `.github/workflows/`, `docs/maintenance.md`, `docs/protocol-upgrade-runbook.md` |

None of these exist yet beyond empty directories and compiling skeletons.

## Building and checking

Toolchains are pinned: Rust 1.99.1 (`rust-toolchain.toml`), Go 1.27.4, Node.js 26.13.1. The
same commands CI runs:

```sh
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace

# in each module listed in go.work
go vet ./... && go test ./...

cd testees/js && npm ci && npx tsc --noEmit && npx tsc && node --test "dist/**/*.test.js"

scripts/check-no-em-dash.sh
```

`cargo run -p shapekit-cli -- pins verify` needs network access. Nothing else does.
